---
title: "GameInstance：レベルを移動しても値を引き継ごう"
---

`Open Level`でレベルを移動しても、Level Blueprintごとの変数は共有されません。**同じゲーム実行中に値を引き継ぐには、GameInstanceに保存します。**

```text
変更前: L_Stage1のScore=10 → Open Level → L_Stage2のScore=0
変更後: L_Stage1 → GameInstance.Score=10 → Open Level → L_Stage2がGameInstanceから10を読む
```

このページでは、まず`10→0`を確かめ、GameInstanceを使う形へ変更して`10→10`を確かめます。PIEを停止して実行し直すと値は初期値へ戻ります。

<Prerequisites>

- Unreal Engine 5.7.4のThird Person（Blueprint）テンプレートから新規作成したプロジェクトを開いている
- Level Blueprintで変数を作り、`BeginPlay`、`Print String`、`Open Level`を使える

</Prerequisites>

<Section title="レベルを移動すると変数はどうなる？" goal="別々のLevel Blueprint変数は共有されないことを、10と0の表示で確かめます。">

### STEP 1｜2つのレベルを作ろう

<Action title="新しいBasicレベルを2つ保存する">

元のThird Personレベルを残したまま、空の作業用レベルを2つ作ります。どちらも複製ではなく、`Basic`から新規作成します。

Content Drawerで`Lesson9/Maps`フォルダを作ります。元のThird Personレベルを開いた状態で、メニューから`File`→`New Level`→`Basic`→`Create`を選びます。続けて`File`→`Save Current Level As...`を選び、`Lesson9/Maps`に`L_Stage1`として保存します。

もう一度`File`→`New Level`→`Basic`→`Create`を選び、`Lesson9/Maps`に`L_Stage2`として保存します。元のレベルは上書きしません。

</Action>

<Verify title="2つの別々のレベルがある">

Content Drawerの`Lesson9/Maps`に、別々のレベルアセット`L_Stage1`と`L_Stage2`があり、元のThird Personレベルも残っています。

</Verify>

### STEP 2｜スコアが引き継がれないことを確認しよう

<Action title="L_Stage1でScoreを10にしてから移動する">

`L_Stage1`を開いて`Level Blueprint`を開き、My Blueprintで整数型のメンバー変数`Score`を作ります。Compileし、初期値が`0`であることを確認します。

`Event BeginPlay`から`Set Score`を実行し、値を`10`にします。`Set Score`の実行出力から`Print String`、`Delay`、`Open Level`の順に白い実行線をつなぎます。`Delay`の`Duration`は`2.0`、`Open Level`の`Level Name`は`L_Stage2`です。

`Get Score`の値出力を`ToString (int)`経由で`Print String`の`In String`につなぎます。`Print String`の`Duration`は`1.8`にし、画面表示を有効にします。`Get Score`と`ToString (int)`は値を渡す純粋ノードなので、白い実行ピンはありません。

```text
白い実行線:
BeginPlay → Set Score (10) → Print String → Delay (2.0) → Open Level (L_Stage2)

データ線:
Get Score → ToString (int) → Print String.In String
```

`L_Stage1`のLevel BlueprintをCompileし、レベルをSaveします。

</Action>

<Action title="L_Stage2に別のScoreを作る">

`L_Stage2`を開いて`Level Blueprint`を開きます。整数型のメンバー変数`Score`を新しく作り、Compileして初期値が`0`であることを確認します。これは`L_Stage1`の`Score`とは別の変数です。

`Event BeginPlay`から`Print String`へ白い実行線をつなぎます。`L_Stage2`側の`Get Score`から`ToString (int)`を経由して`Print String`の`In String`へデータ線をつなぎ、`Print String`の`Duration`を`5.0`にします。画面表示も有効にします。2つの純粋ノードに白い実行ピンはありません。

Level BlueprintをCompileし、レベルをSaveします。

</Action>

<Verify title="10のあとに0が表示される">

`L_Stage1`からPlayします。最初に`10`が表示され、2秒後に`L_Stage2`へ移動すると`0`が表示されます。同じ`Score`という名前でも、それぞれのLevel Blueprintが別のメンバー変数を持つため、自動では値が共有されません。

</Verify>

</Section>

<Section title="GameInstanceを使ってスコアを引き継ぐ" goal="BP_LessonGameInstanceのScoreを使い、同じゲーム実行中に10を次のレベルへ渡します。">

<Concept title="GameInstanceが値を保つ範囲">

GameInstanceは、**1回のゲーム実行中に使われ、`Open Level`でレベルを移動しても残るオブジェクト**です。複数のレベルから同じGameInstanceの変数を読み書きできます。PIEをStopするとその実行が終わり、次のPlayでは新しいGameInstanceが作られます。

</Concept>

### STEP 3｜GameInstanceを作ろう

<Action title="GameInstance Blueprintを作ってプロジェクトに設定する">

Content Drawerで`Lesson9/Blueprints`フォルダを作ります。その中で`Blueprint Class`を作成し、親クラスに`GameInstance`を選び、名前を`BP_LessonGameInstance`にします。

My Blueprintで整数型の`Score`を作り、初期値を`0`にしてCompile/Saveします。

次に`Edit`→`Project Settings`→`Maps & Modes`を開き、`Game Instance`欄の`Game Instance Class`に`BP_LessonGameInstance`を指定します。この設定はプロジェクト全体で使われます。Blueprintを作っただけでは有効になりません。PIE中ならStopしてから設定後にPlayし直します。

</Action>

### STEP 4｜Scoreを別のレベルへ引き継ごう

<Action title="L_Stage1からGameInstanceへScoreを書く">

`L_Stage1`のLevel Blueprintを開き、前の手順で表示に使ったLevel Blueprintの`Score`は、変数自体を削除せず、これからは読み書きしません。`Event BeginPlay`からGameInstanceをCastし、成功した場合だけ値を書いてレベルを移動する形にします。

次の順でノードと線をつなぎます。

1. `Get Game Instance`を置きます。これは値を返す純粋ノードで、白い実行ピンはありません。
2. `Get Game Instance`の`Return Value`から`Cast To BP_LessonGameInstance`の`Object`へデータ線をつなぎます。
3. `Event BeginPlay`の白い実行出力からCastの白い実行入力へ、実行線をつなぎます。実行線は`Get Game Instance`を通りません。
4. Cast成功の白い実行出力から`Set Score`を実行します。`Target`には`As BP_LessonGameInstance`をつなぎ、値に`10`を設定します。
5. `Set Score`の実行出力から`Print String`、`Delay`、`Open Level`の順に実行線をつなぎます。Delayは`2.0`、`Open Level`の`Level Name`は`L_Stage2`です。
6. Castの`As BP_LessonGameInstance`から`Get Score`の`Target`へデータ線をつなぎます。`Get Score`の値出力から`ToString (int)`を経由して、`Print String`の`In String`へデータ線をつなぎます。`Print String`は`Duration`を`1.8`、画面表示を有効にします。

```text
白い実行線:
BeginPlay → Cast To BP_LessonGameInstance → 成功 → Set Score (10)
          → Print String → Delay (2.0) → Open Level (L_Stage2)

データ線:
Get Game Instance.Return Value → Cast.Object
Cast.As BP_LessonGameInstance → Set Score.Target
Cast.As BP_LessonGameInstance → Get Score.Target
Get Score → ToString (int) → Print String.In String
```

Castの`Cast Failed`実行出力から別の`Print String`へ実行線をつなぎ、`GameInstanceの設定を確認`と表示します。失敗側から`Set Score`や`Open Level`へ線をつながないため、Castに失敗した場合はレベル移動しません。

</Action>

<Action title="L_Stage2から同じGameInstanceのScoreを読む">

`L_Stage2`のLevel Blueprintも、GameInstanceの値を読む形にします。Level Blueprint側の`Score`変数は削除せず、表示には使いません。`Get Game Instance`の`Return Value`から`Cast To BP_LessonGameInstance`の`Object`へデータ線をつなぎ、`Event BeginPlay`からCastへ白い実行線をつなぎます。`Get Game Instance`は純粋ノードなので白い実行ピンはありません。

Cast成功の実行出力から`Print String`を実行します。`As BP_LessonGameInstance`をTargetにした`Get Score`を`ToString (int)`経由で`Print String`の`In String`へつなぎます。`Print String`の`Duration`は`5.0`、画面表示は有効にします。

Castの`Cast Failed`実行出力から、別の`Print String`へ実行線をつなぎ、`GameInstanceの設定を確認`と表示します。Compile/Saveして、Level Blueprintとレベルを保存します。

</Action>

<Recovery title="Cast失敗の表示が出るとき">

`GameInstanceの設定を確認`が表示されたら、`Edit`→`Project Settings`→`Maps & Modes`→`Game Instance`の`Game Instance Class`が`BP_LessonGameInstance`か確認します。設定後はPIEをStopしてPlayし直します。Cast成功からSet/Getへ続く接続も確認します。

</Recovery>

<Recovery title="L_Stage2で10が表示されないとき">

- `L_Stage1`ではCast成功から`Set Score`が実行され、`Target`が`As BP_LessonGameInstance`、値が`10`か確認します。
- 両方のレベルで`Get Game Instance.Return Value`がCastの`Object`につながり、Cast成功の`As BP_LessonGameInstance`がGet/SetのTargetになっているか確認します。
- `Open Level`の`Level Name`が`L_Stage2`か確認します。名前が違うと移動先が異なります。
- 表示に使う`Get Score`のTargetが、Level Blueprintのメンバー変数ではなくGameInstanceか確認します。

</Recovery>

<Verify title="同じPIE中に10を引き継ぐ">

`L_Stage1`からPlayし、`L_Stage1`で`10`、`L_Stage2`へ移動したあとも`10`が表示されます。両方の表示がGameInstanceの`Score`を使っていることを確認します。

</Verify>

<Section title="GameInstanceはいつまで残る？" goal="PIE停止後は値が初期化されることを確認し、レベル間の一時的な値と保存データを区別します。">

### STEP 5｜ゲームを終了したらどうなる？

<Action title="L_Stage2から新しくPlayする">

PIEをStopし、エディタで`L_Stage2`を開きます。その状態からPlayします。新しいGameInstanceには`L_Stage1`から値を書いていないため、`L_Stage2`には初期値の`0`が表示されます。

</Action>

<Action title="L_Stage1からPlayして10を渡す">

PIEをStopし、`L_Stage1`を開いてPlayします。`L_Stage1`で`10`を設定し、`L_Stage2`へ移動した後も`10`が表示されることを確認します。

</Action>

<Verify title="PIEの開始位置で表示が変わる">

- `L_Stage2`から新しくPlayすると`0`が表示される
- Stopして`L_Stage1`からPlayすると、`L_Stage1`と`L_Stage2`の両方で`10`が表示される

</Verify>

<Concept title="値の寿命に合わせて置き場所を選ぶ">

どの値もGameInstanceに移す必要はありません。**レベル内だけで使う値はLevel Blueprint、同じ実行中にレベルをまたぐ値はGameInstance、実行終了後も残すデータはSaveGame**というように、必要な期間に合わせて選びます。SaveGameは保存と読み込みを実装したときに永続化されます。この手順ではSaveGameを作りません。

|置き場所|値を使える範囲|このページでの例|
|---|---|---|
|Level Blueprintのメンバー変数|そのLevel Blueprintを使うレベル内|変更前の各レベルの`Score`|
|GameInstance|同じゲーム実行中のレベル間。PIE Stopで終了|`L_Stage1`から`L_Stage2`へ渡す`Score`|
|SaveGame|保存・読み込みを実装した後は、実行をまたいで利用可能|今回は実装しない|

</Concept>

</Section>
