---
title: "Event Dispatcher：HPの変化を通知しよう"
---

今回は、以前作ったゲームのHP表示を改良します。今までは、プレイヤーのCharacterがHUDの関数を直接呼び出していました。この仕組みを、HPが変わったことを通知し、HUDがその通知を受け取る仕組みに変更します。新しいActorやWidgetは作りません。

<Prerequisites>

- Unreal Engine 5.7.4を使う
- 「デザイナー07：トラップとダメージ」を完成させたプロジェクトを開く
- `BP_AdventureCharacter`、`WBP_PlayerHUD`、`Health`、`fnSetHP(NewHP: Float)`がある
- トラップでダメージを受けると、CharacterのHPが減る

</Prerequisites>

<Section title="今までの仕組みと、その問題点" goal="直接呼び出しの仕組みを確認し、通知方式が役立つ場面を理解する">

### STEP 1｜今までのHP更新を確認しよう

<Action title="既存の直接呼び出しを観察する">

1. Playし、トラップを踏みます。HUDのHP表示が減ることを確認してPlayを止めます。
2. `BP_AdventureCharacter`のEvent Graphを開き、`Event AnyDamage`付近で`fnSetHP`を呼び出している箇所を探します。

```text
Damage → Healthを更新 → HUD.fnSetHP → HP表示を更新
```

</Action>

<Concept title="今の作り方も正しい">

表示処理を`fnSetHP`にまとめれば、HUDの見た目だけを変えるときにCharacterを変更せずに済みます。特定の相手に処理を頼むなら、直接呼び出す方法はシンプルで合理的です。

</Concept>

<Verify title="直接呼び出しを確認する">

- トラップを踏むと、HUDのHP表示が減る
- `Event AnyDamage`付近に`fnSetHP`の呼び出しがある
- `fnSetHP`がHUDの表示を更新する

</Verify>

### STEP 2｜今の作り方で困ることはある？

最初の変更要求を考えます。**「HPを表示するWidgetを、別のWidgetに交換したい！」**

今のままでは、Characterが特定のHUDの`fnSetHP`を直接呼び出します。Widgetの交換に伴って、Characterが持つHP処理の参照先や呼び出し先も見直す必要が生じることがあります。

|役割|担当|
|---|---|
|HPの計算と管理|Character|
|HPの表示|HUD|

HPの計算は変わっていないのに、表示先の変更によってCharacterのHP処理まで修正するのは、できれば避けたいですよね。

ダメージ記録やHPに応じた音など、別の独立した機能が必要になった場合も同じです。Characterが各機能の呼び出し先まで知っていると、**機能変更が本来別の責務を持つCharacterに波及します**。

Characterは「HPが変わった！」という事実だけを知らせて、その後の処理は受け取った側に任せられないでしょうか？

<Concept title="Event Dispatcherとは？">

Event Dispatcherは、**起きた事実を通知する仕組み**です。`Call`は通知を発行し、`Bind`は通知を受けたときに実行するイベントを登録します。Characterは、受信側の具体的な関数を知る必要がありません。

```text
Character → OnHealthChanged → HUD → fnSetHP
```

</Concept>

</Section>

<Section title="Event DispatcherでHP更新を改良する" goal="HPの変更をCharacterから通知し、HUDで受け取って表示を更新する">

### STEP 3｜CharacterからHPの変化を通知しよう

<Action title="HP変更後にEvent DispatcherをCallする">

#### 1. Dispatcherを作成する

`BP_AdventureCharacter`のMy Blueprintで、`Event Dispatchers`の`+`を押します。名前を`OnHealthChanged`にし、Inputsに次の引数を追加します。

|項目|設定|
|---|---|
|名前|`NewHP`|
|型|`Float`|

#### 2. HP更新後に通知をつなぐ

Event Graphの`Event AnyDamage`で、既存の`Set Health`の**白い実行出力**の後に`Call OnHealthChanged`を置きます。`Get Health`の**Float出力**を、Callの`NewHP`入力につなぎます。

|ノード|白い実行線|Floatデータ|
|---|---|---|
|既存の`Set Health`|出力から`Call OnHealthChanged`の実行入力へ|—|
|`Call OnHealthChanged`|実行出力から既存の死亡判定`Branch`へ|`Get Health`から`NewHP`へ|
|既存の死亡判定`Branch`|True側は既存の死亡処理を維持。False側は既存の通常処理を維持|TrueはHPが0以下、Falseは通常側|

**Callは死亡判定より前**に置きます。HPが0または負の値になった場合も、更新後のHPを通知してから既存の死亡判定を実行できます。HPが正の値なら、既存の通常側の動作をそのまま続けます。

`Branch`のFalse側にある古いHUDの`fnSetHP`呼び出しだけを外し、残りの通常処理は維持します。HP計算や死亡処理を作り直す必要はありません。

設定後、`BP_AdventureCharacter`をCompileしてSaveします。

</Action>

<Verify title="HP更新の後に通知される">

- `Set Health`の後に`Call OnHealthChanged`が実行される
- `Get Health`のFloat値が`NewHP`に渡る
- Callの後に既存の死亡判定Branchが実行される
- BranchのFalse側に古いHUDの`fnSetHP`呼び出しが残っていない
- BranchのTrue側にある既存の死亡処理が残っている

</Verify>

### STEP 4｜HUDで通知を受け取ろう

<Action title="HUDをBindして初期HPを表示する">

#### 1. Characterを取得してDispatcherをBindする

`WBP_PlayerHUD`のEvent Graphで、Widgetの初期化イベント`Event OnInitialized`から始めます。`Get Player Character`の`Return Value`を`Cast To BP_AdventureCharacter`の`Object`につなぎます。

Cast成功の白い実行出力から`Bind Event to OnHealthChanged`を実行し、Cast結果をBindの`Target`につなぎます。

#### 2. 通知を既存関数へ渡す

Bindの赤い`Event`ピンから、Dispatcherのシグネチャに一致するCustom Eventを作ります。名前を`ReceiveHealthChanged`にします。引数は`NewHP`（Float）です。

|接続|つなぐ先|
|---|---|
|Bindの赤い`Event`ピン|`ReceiveHealthChanged(NewHP: Float)`|
|Custom Eventの白い実行出力|既存の`fnSetHP`の実行入力|
|Custom Eventの`NewHP`（Float）|`fnSetHP`の`NewHP`入力|

#### 3. Bindの後に現在のHPを表示する

Bindより前に発行された通知は、後からBindしても再生されません。**CastとBindが成功した後**、Cast結果からCharacterの現在の`Health`を取得し、既存の`fnSetHP`へ渡して初期表示を設定します。

|接続|つなぐ先|
|---|---|
|Bindの白い実行出力|`fnSetHP`の白い実行入力へ|
|Cast結果|Characterの`Health`を読む参照元|
|`Get Health`のFloat出力|`fnSetHP`の`NewHP`入力|

続いて`BP_AdventureCharacter`の`Event Possessed`を開きます。`Set HUD`と`Add to Viewport`の間にある、**初期HP表示専用の`fnSetHP`だけ**を外し、白い実行線をつなぎ直します。HUDの生成・保存・`Add to Viewport`と、鍵表示など他の処理は維持します。初期表示はHUD自身が行うため、HPを二重に更新しません。

`WBP_PlayerHUD`と`BP_AdventureCharacter`をCompileしてSaveします。

</Action>

<Verify title="初期HP、ダメージ、既存機能を確認する">

- Play開始時に、現在のHPがHUDに表示される
- トラップでダメージを受けると、HUDのHP表示が変わる
- HPが0になると既存の死亡処理が動き、レベル再開も従来どおり動く
- 既存の鍵表示が動く
- `Event Possessed`の初期HP表示用`fnSetHP`が残っていない

</Verify>

<Recovery title="通知されない、または初期HPが表示されないとき">

- Castが失敗する場合は、`Get Player Character`の`Return Value`がCastの`Object`につながり、対象が`BP_AdventureCharacter`か確認します。
- Bindが実行されない場合は、`Event OnInitialized`からCastへ、Cast成功ExecからBindの白い実行入力へ線があるか確認します。
- 通知を受け取れない場合は、Bindの`Target`がCast結果で、赤い`Event`ピンから作った`ReceiveHealthChanged`がDelegateに結線されているか確認します。
- HP値が変わらない場合は、`Get Health`→CallのFloat `NewHP`、およびCustom EventのFloat `NewHP`→`fnSetHP`の`NewHP`がつながっているか確認します。
- 初期HPが出ない場合は、Bind成功後に現在の`Health`を取得して`fnSetHP`へ渡しているか確認します。`Event Possessed`の古い初期表示呼び出しが残っていないことも確認します。
- HP0や再開後に死亡処理が動かない場合は、Callの白い実行出力が既存Branchにつながり、True側の死亡処理が残っているか確認します。

</Recovery>

### STEP 5｜直接呼び出しとの違いを理解しよう

```text
前：Character → WBP_PlayerHUD.fnSetHP
後：Character → OnHealthChanged(NewHP) → BindしたHUD → fnSetHP
                                  └→ Bindした記録システム
```

|比較点|直接呼び出し|Event Dispatcher|
|---|---|---|
|依頼のしかた|特定の相手に処理を頼む。シンプル|起きた事実を通知する|
|Characterが知る相手の関数|知っている|受信側の具体的な関数は知らない|
|受信先を追加するとき|呼び出し元を変更する場合がある|受信側がDispatcherへBindする|
|通知先がないとき|相手の参照を確認する|Bind先がなければCallしても何も起動しない。ゲーム進行が成功するとは限らない|

この通知方式で外せるのは、**HP変更処理から特定HUDの更新関数への依存**です。直接呼び出しが間違いということではありません。また、CharacterにHUD生成と鍵表示の関係は残るため、Character全体のHUDクラス依存がなくなるわけではありません。別のHUDクラスへ無修正で差し替えられるとも限りません。

- **直接呼び出し:** この相手に、この処理をしてほしい
- **Event Dispatcher:** こんな出来事が起きました！
